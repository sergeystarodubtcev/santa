# ☕🎅 Тайный Санта Кофеманьяков

Сайт для кофеманьячного Тайного Санты: красивая главная с анимациями (снег, летающие сани Деда Мороза, кофе, который наливается в чашку), регистрация, личные кабинеты, админка с жеребьёвкой и статусами посылок.

![Превью](public/img/og.png)

## Что внутри

**Главная** (`index.html`)
- Аватар и подпись Кофеманьяков, превью поста из Telegram-чата с обсуждением.
- Живой счётчик участников: каждый, кто заполнил анкету, сразу добавляется в счётчик (обновление раз в 15 секунд, с анимацией и тостом «+1 кофеманьяк»).
- Два таймера: до начала отправки (1 декабря) и до её конца (10 декабря).
- Блоки «Как это работает» и «Правила» (бюджет, сроки, чёрный список, аллергии, мерч, нечётное число участников).
- Огромный блок участия: летают сани, падают кофейные зёрна и снег. Кнопка «Хочу участвовать» при нажатии наливает кофе, трясётся и взрывается конфетти, потом открывается анкета:
  1. **О себе** (если ещё нет аккаунта): имя, телефон, ник в Telegram, пароль. Можно войти в существующий аккаунт.
  2. **Посылка**: ФИО, телефон, адрес **ближайшего ПВЗ Ozon** (домашний адрес не принимается — защита участников), пожелания, тематика (кофейное / некофейное / удивите меня), особые пометки («у меня аллергия на инфьюзы»), галочка «подтверждаю участие и дальнейшую отправку».
- При регистрации обязательна галочка **согласия на обработку персональных данных** (152-ФЗ), текст политики — `privacy.html`. Участник может сам удалить аккаунт и данные в кабинете (отзыв согласия).

**Личный кабинет** (`cabinet.html`): вход по нику в Telegram или телефону и паролю.
- «Кому я дарю»: после жеребьёвки тут имя, адрес, телефон, пожелания и пометки получателя. Есть поле для трек-номера и кнопка «Я отправил подарок».
- «Мой подарок»: когда ваш Санта отметит отправку, здесь появится **«Вам подарок от Деда Мороза!»**, а потом кнопка «Я получил».
- Уведомления, в том числе большой баннер **«У ВАС 3 ДНЯ, ЧТОБЫ УСПЕТЬ ОТПРАВИТЬ ПОДАРОК»**: дни считаются автоматически до конца срока отправки. Баннер виден на всех страницах сайта.
- Редактирование анкеты; выйти из игры можно до жеребьёвки.

**Админка** (`admin.html`, вход по паролю)
- Статистика: аккаунты, участники, чёрный список, сколько отправили и сколько получили.
- **Модерация**: каждая анкета сначала «на модерации». Организаторы одобряют или отклоняют (с причиной — участник её увидит). В жеребьёвку попадают **только одобренные**. Есть фильтр «только на модерации» и кнопка «одобрить всех ожидающих».
- **«Раскидать людей»**: случайная жеребьёвка в одну общую цепочку. Каждый дарит следующему, никто не дарит сам себе, нечётное число участников не мешает. После жеребьёвки новые анкеты больше не принимаются.
- Таблица пар со статусами (их можно поправить вручную) и трек-номерами.
- Таблица участников с поиском, чёрным списком и удалением.
- Настройки: даты отправки (по МСК), бюджет, баннер-объявление на сайте, ссылка на чат, открыть или закрыть регистрацию.
- Рассылка уведомления в личные кабинеты.
- Бэкап и восстановление базы (JSON), выгрузка участников в CSV.

## Как это устроено

```
public/            фронтенд (чистые HTML/CSS/JS, без сборки)
  js/core.js       вся логика: регистрация, анкеты, жеребьёвка, уведомления, API-роутер
  js/api.js        клиент API + демо-режим
server/index.js    бэкенд на Node.js без зависимостей; раздаёт public/ и /api/*
test/              тесты логики (node --test)
```

Логика (`core.js`) общая для сервера и браузера. Если фронтенд не находит бэкенд (например, на GitHub Pages ещё не задан адрес API), включается **демо-режим**: всё работает, но данные хранятся только в этом браузере. Пароль админки в демо: `admin`. Внизу страницы при этом висит жёлтая плашка.

Пароли хранятся как хэши scrypt, сессии подписаны HMAC, на вход и регистрацию стоит ограничение по количеству попыток.

## Запуск локально

```bash
npm start
```

Откройте http://localhost:3000. Пароль админки выводится в консоль при первом запуске. Задать свой: `ADMIN_PASSWORD=... npm start`.

```bash
npm test
```

## Деплой

### 1. Фронтенд на GitHub Pages

Workflow `.github/workflows/pages.yml` на каждый push прогоняет тесты и публикует папку `public/` на GitHub Pages.
Если Pages ещё не включены: **Settings → Pages → Source: GitHub Actions**, затем перезапустите workflow.

### 2. Бэкенд (Render.com, бесплатно)

1. На https://render.com: **New → Blueprint**, выберите этот репозиторий (подхватится `render.yaml`).
2. Задайте `ADMIN_PASSWORD`.
3. Бесплатный Render стирает диск при перезапуске, поэтому базу лучше зеркалить в приватный GitHub-репозиторий:
   - создайте приватный репозиторий, например `santa-data`;
   - создайте fine-grained токен (GitHub → Settings → Developer settings → Fine-grained tokens) с доступом только к `santa-data` и правом **Contents: Read and write**;
   - в Render задайте `GITHUB_DATA_REPO=ваш-логин/santa-data` и `GITHUB_TOKEN=...`.
   Сервер при старте загружает базу оттуда и сохраняет каждое изменение.
4. Скопируйте адрес сервиса, например `https://coffeemaniacs-santa.onrender.com`.

Бэкенд сам раздаёт и фронтенд, так что сайт сразу работает по этому адресу.

### 3. Связать GitHub Pages с бэкендом

**Settings → Secrets and variables → Actions → Variables → New variable**: `API_URL = https://coffeemaniacs-santa.onrender.com`, затем перезапустите workflow. После этого Pages работает с настоящей базой, а демо-плашка исчезает.

### Альтернатива: Docker (любой VPS, Fly.io, Railway)

```bash
docker build -t santa .
```

```bash
docker run -d -p 3000:3000 -v santa-data:/data -e ADMIN_PASSWORD=секрет santa
```

## Переменные окружения

| Переменная | Что это |
|---|---|
| `PORT` | порт (по умолчанию 3000) |
| `DATA_DIR` | папка с базой `db.json` (по умолчанию `./data`) |
| `ADMIN_PASSWORD` | пароль админки (если не задан, генерируется и пишется в лог) |
| `SECRET` | ключ подписи сессий (если не задан, генерируется) |
| `CORS_ORIGIN` | откуда разрешены запросы (по умолчанию `*`) |
| `GITHUB_DATA_REPO`, `GITHUB_TOKEN`, `GITHUB_DATA_PATH` | зеркалирование базы в приватный GitHub-репозиторий |
